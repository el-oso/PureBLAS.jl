# workspace self-alias lint baseline — claim-inside-a-claim pairs REVIEWED AS LEGAL, each with its reason.
# The lint fails BOTH ways: a pair not listed here is a new finding, and a line here that no longer occurs
# is stale (a removed caller must not leave a rubber stamp behind). Regenerate the raw list with
#   julia --project=. test/workspace_lint.jl --baseline
# and then re-justify every line by READING it. A line whose reason you cannot restate is not a pass.
#
# The lint is name-level and conservative: it treats a claim as live to the end of the enclosing method and
# merges all methods of a name, so sequential re-claims, mutually exclusive if/ternary arms, and
# claim-once-then-thread-it-down all show up here. That is the intended trade — over-approximate, then
# justify in writing, exactly as req8_lint.jl does with its literals.
#
# HISTORY WORTH KEEPING: this file once carried 16 pairs. Seven of them — every `X -> X` self-edge —
# were PHANTOMS produced by a scanner bug, not by the code: `_bodies` attributed lines to the preceding
# definition, so a docstring written above a function had its indented signature lines read as calls by
# whatever was defined before it. Where two methods of one name sat adjacent, that manufactured a self-call.
# They were baselined with confident-sounding reasons ("the pair exists only because all methods of a name
# are merged…") that described an artifact. The lesson is about baselines generally: a justification
# written for a finding you did not verify is indistinguishable from one written for a finding that is
# real. Re-derive, do not re-read.
#
# 2026-09-02 — TWO MORE SCANNER DEFECTS FIXED, and this list is re-derived from source, not copied:
#   * the declared `_lacn2_estimate` callback edges were INERT. `applyf`/`apply!` are anonymous-function
#     ASSIGNMENTS, which `_bodies` did not record as definitions, so `(g for g in gs if g in names)` threw
#     both edges away in silence while the header advertised them as the thing that closes the callback
#     hole. `_bodies` now sees `name = function …` / `name = … ->`, and an unresolvable declared edge is
#     an ERROR. The three `lacn2*` lines below are that fix landing — they are NEW, and they are real.
#   * the docstring rule fired on an INDENTED `"""` too, so the llvmcall IR string inside `_prefetch`
#     (blas3/gemm.jl:68/75) killed attribution for the rest of that function. That direction HIDES
#     findings. Triple-quoted literals are now skipped wherever they sit; only a column-0 `"""`/`raw"""`
#     stops attribution.

# --- 2026-09-04, stage 2 of the arena conversion: the three
#       L3Workspace.lacn2{s,v,x}  _lacn2_estimate -> _lacn2_estimate
# lines are GONE, and the reason is a change of MECHANISM, not a re-judgement of the old one.
#
# WHY THEY EXISTED (re-derived from the scanner, not copied from the entry they replace): a pair is
# emitted when `fld ∈ claims[f]` and `fld ∈ claims[g]` for some `g ∈ reach(f)`. `_lacn2_estimate`
# claimed lacn2x/lacn2v/lacn2s because its body called `_lacn2e_bufs`, and `g == f` was reachable
# because `_CALLBACK_EDGES` declares `_lacn2_estimate -> apply!/applyf` while merged-name attribution
# puts the callers' own `_lacn2_estimate(…)` calls inside those closures' bodies. Take away either half
# and the pair cannot be produced.
#
# WHY THEY ARE GONE: the first half. `_lacn2_estimate` (trsen.jl) now opens an `@scope` and takes
# `borrow!(arn, V, n)` ×2 + `borrow!(arn, Int, n)` from the arena, so its body names no `L3Workspace`
# field at all and `claims["_lacn2_estimate"]` is empty. The `lacn2*` fields and `_lacn2e_bufs` still sit
# in workspace.jl awaiting the serial field-deletion pass, but nothing CALLS the accessor, so there is no
# claimant left to pair with. The DECLARED EDGE ITSELF STAYS — `_CALLBACK_EDGES` still names
# `apply!`/`applyf`, and it must, because it is what would catch a future field re-claim through the
# callback; only the finding it produced is gone.
#
# WHAT REPLACES THE SAFETY ARGUMENT, since the lint no longer makes one here: the arena's hazard is a
# HANDLE outliving its `@scope`, which is a different question from a field being re-claimed, and
# `@scope` cannot see it (it checks the TOKEN). It is audited by reading, at each converted site, and the
# audit is written there: trsen.jl (`_lacn2_estimate`, and the `scref` scope that must span the estimate
# AND the `sep = …` read) and trrfs.jl (`wt` is CAPTURED by `applyf`). RE-READ THOSE if a new caller of
# `_lacn2_estimate` appears or either closure grows a call.
